# 01 会话转录存储（cline / codex / gemini-cli / OpenHands / claude-code）

> agent-persistence 轮第 1 路。四路线对比一句话：**codex（append-only JSONL+ordinal+文件锁+倒序读，工程最完整）**、**cline（JSON 全量重写+原子 tmp/rename+hash 校验旁挂压缩）**、**claude-code【还原源码】（JSONL+parentUuid 链+旁挂 entry+懒物化+墓碑删除，细节最重）**、**gemini-cli（双层：旧 logs.json 读改写 + 现役 chats/*.jsonl 追加）**、**OpenHands（每事件一 JSON 文件+25 条页缓存+写时脱敏，对象存储友好）**。
> ⚠️ 对旧档案的修正：**cline 现基线（cfe9cadab9）转录不是 JSONL**——`.messages.json` 为 pretty-printed JSON、每 turn 全量重写；旧资料按 JSONL 引用需修正。除标注外均为【核心】；claude-code 全部【还原源码】。

### 1.2 文件 schema

- **messages 文件 payload**（`session-data.ts#buildMessagesFilePayload:327-352`）：`{version:1, updated_at, agent: "lead"|"subagent"|"teammate", sessionId, taskType?, origin{source, mode, sessionId, parentThreadId?, subagent?, version?, trigger?}, messages[], system_prompt?}`——origin.mode 区分 user/automation/subagent/team，人机发起事后可辨。
- **消息行**（`shared/src/llms/messages.ts:117-177`）：`{role: user|assistant, content: string|ContentBlock[], id?, agent?, sessionId?, metadata?, modelInfo?{id,provider,family?}, metrics?{inputTokens,outputTokens,cacheReadTokens,cacheWriteTokens,cost}, ts?}`；ContentBlock 8 种：`text/file/image/media/tool_use/tool_result/thinking/redacted_thinking`。turn 结束时 per-turn metrics+ts 盖章到 assistant 消息（`session-data.ts#withLatestAssistantTurnMetadata:122-193`，无 per-turn metrics 才回退 run 总量）。
- **manifest**（`session/models/session-manifest.ts:6-28`）：`version/session_id/source/pid/started_at/ended_at?/exit_code?/status/interactive/provider/model/cwd/workspace_root/team_name?/enable_tools/enable_spawn/enable_teams/prompt?/metadata?/messages_path?/compaction_path?`。
- **compaction 旁挂**（`session/models/session-compaction.ts:25-34`）：`{version:1, updated_at, conversation_id?, source_message_count, source_prefix_hash?, source_last_message_key?, messages[](摘要), system_prompt?}`。恢复前校验（`projectSessionCompactionState:161-190`）：canonical 前 `source_message_count` 条的 sha256 前缀 hash 匹配（或 legacy boundary key 匹配）才投影拼接 `摘要+边界后原文`，否则整个 sidecar 丢弃——**canonical 原文永不被摘要覆盖**。hash 细节：域分隔串 `"cline-session-compaction-source-v2\n"`+条数+逐条 JSON，**故意不含 id/ts**（传输身份每轮重生成，hash 它会导致校验永假，v1→v2 的真实踩坑注释 :76-131）；user 文本先过 `formatDisplayUserInput` 归一。
- **SQLite DDL**：`tasks.db` = `agenda_tasks`（26 列，含 `revision/approved_revision` 审批-版本绑定、`CHECK(scope='workspace'↔workspace_root 非空)`、时间窗+优先级索引）+ `agenda_task_runs`（`UNIQUE(task_id,attempt)`、部分唯一索引 `agenda_task_runs_one_active_idx WHERE status IN ('starting','running')`——**单活跃 run 由索引保证**）+ `agenda_task_automation`（`tasks/store/task-schema.ts:4-87`）；`cron.db` = `cron_specs/cron_runs/cron_event_log`（claim_token/claim_until_at 租约抢占列、dedupe_key 事件去重索引，`cron/store/cron-schema.ts:11-117`）；均 `PRAGMA journal_mode=WAL; busy_timeout=5000; foreign_keys=ON`。`sessions.db` 的 sessions 表带 `status_lock INTEGER`（OCC 版本列）与 `transcript_path`（`shared/src/db/sqlite-db.ts:186-225`）。

### 1.3 写路径、并发与懒创建

- 原子写：`writeFileAtomic` = `${path}.${pid}.${uuid}.tmp` → write → **fsync** → rename → 目录 fsync（best-effort），失败清理 tmp（`stores/atomic-file.ts:23-52`）；索引/队列用简化版 `atomicWriteJson`（`file-session-service.ts:44-48`）。
- 并发：更新会话状态走 statusLock 乐观锁 + `withOccRetry` 重试（`session-data.ts:408-434`）；DB 行丢失时从磁盘 manifest **重新收养**（re-adopt）行，消息写入不允许静默建孤儿文件（`session-manifest-store.ts:181-196`）。
- **懒创建时机**：`ensureSessionPersisted` 在首个被接受 turn 的 `executeTurn` 入口调用（`runtime/host/local-runtime-host.ts:1742`）；**带种子的会话（fork/checkpoint 恢复/丢失找回）例外——启动即落盘**，否则 hub 重启会从空文件重建静默清空对话（:955-975 注释）；turn 中断（aborted exchange）也即时持久化防丢（:1835-1848）。
- checkpoint：**无独立文件**，是 git 对象——私有 index（scratch 目录，`GIT_INDEX_FILE` 隔离）+ `write-tree`+`commit-tree`（消息 `"index on cline checkpoint"` / `"untracked files on cline checkpoint"`，untracked 组树作第三父，镜像 `stash create --include-untracked`）；ref 命名空间 `refs/cline/checkpoints/{sessionId}/`；恢复是事务：先 `git stash push --include-untracked` 存入私有 ref `refs/cline/restore-transactions/<uuid>` 可回滚（`hooks/checkpoint-hooks.ts:265-345,432-460`；`session/checkpoint-restore.ts`）。
- 生命周期：删会话级联子会话 + 空目录上卷清理（`file-session-service.ts:217-233`、`session-artifacts.ts#removeSessionDirIfEmpty`）；自动 rotation/容量上限 ❌ 未实现。

## 5. OpenHands @ e8249f00a（经典 Python 版）

### 5.1 布局与事件 schema

- `sessions/{sid}/`：`events/{id}.json`（每事件一文件）、`metadata.json`、`init.json`、`agent_state.pkl`、`llm_registry.json`、`conversation_stats.pkl`、`event_cache/{start}-{end}.json`；多租户 `users/{uid}/conversations/{sid}/…`（`storage/locations.py`）。FileStore 抽象下同一套键既可落本地也可落 S3/GCS（`storage/files.py`）。
- 事件 JSON 顶层键 `TOP_KEYS = [id, timestamp, source, message, cause, action|observation, tool_call_metadata, llm_metrics]`（`events/serialization/event.py:16-26`）；**`cause` 由 Observation 回指 Action id**——因果链在数据模型层（`events/event.py:63-66`）。
- `llm_metrics` 挂载形态：controller 每步 `_prepare_metrics_for_frontend(action)` 给 action 挂精简 `Metrics{accumulated_cost, accumulated_token_usage, max_budget_per_task}`（agent+condenser 合并；长会话只留累计值防膨胀，`controller/agent_controller.py:1180-1215`）。

### 5.2 写路径与并发

- `EventStream.add_event`（`events/stream.py:166-214`）：拒绝已带 id 的事件（防 handler 回灌成环）→ 锁内 `event._id = cur_id; cur_id += 1` + 拷贝当前写页 → **锁外**写 `events/{id}.json` 与页缓存文件；事件 JSON >1MB 打警告（:196-204）。
- **25 条页缓存**：`cache_size=25`；写页满 25 写 `event_cache/{start}-{end}.json`（读时缺页可绕过）；读侧 `search_events(start,end,reverse,filter,limit)` 按 `index - index%25` 对齐整页批量读，缓解远端 FileStore 逐文件读放大（`event_store.py:44-65,116-135,161-172`）；`cur_id` 惰性：列目录取 max 文件名 id+1（:65-81）。
- **写时脱敏入口**：`add_event` 内 `event_to_dict` 后立即 `_replace_secrets(data)` 再入页/落盘——递归替换字符串值中出现的每个 secret 为 `'<secret_hidden>'`，顶层系统字段 `{timestamp,id,source,cause,action,observation,message}` 跳过（stream.py:174-243）。时机=持久化前、分发前（细节见 05 篇）。

### 5.3 读路径与生命周期

- resume：socket 连接 query 带 `latest_event_id`，服务端 `AsyncEventStoreWrapper(event_store, latest_event_id+1)` 只重放其后事件（断点续传，`server/listen_socket.py:45-106`）；attach 时从存储重建 EventStream+StateTracker。
- 生命周期：❌ 无自动 rotation/保留策略（会话删除是显式 API）；轨迹导出时剔除浏览器大对象（`DELETE_FROM_TRAJECTORY_EXTRAS`，serialization/event.py:28-35）。

## 7. 设计结论（≤5）

1. **append-only 主转录 + 可丢弃的旁挂状态是审计正解**：codex（Compacted/TokenUsage/SecurityScore 独立 item）、cline（compaction sidecar hash 校验后才投影，canonical 永不被摘要覆盖）、claude-code（旁挂 entry 家族）三家同构——摘要/快照/成本/风险都是「可丢可重生成」的附属记录，原文链不可变。
2. **恢复必须校验衔接点**：cline 用前缀 sha256（且只 hash 语义字段，id/ts 这类传输身份排除——v1 真踩坑）；codex 用 ordinal 连续性（子 agent 前缀不完整直接拒写）；claude-code 用 parentUuid 前缀跟踪 + compact boundary 截链。**「旁挂状态 + 无校验恢复」= 静默错续事故**（三家注释里各有一款）。
3. **fork 是复制重写而非原地分叉，且必须重播种旁挂记录**：codex 双 id 文件名+forked_from_id 血统；claude-code 拷消息 + 重播种 contentReplacement（漏种=缓存击穿真实事故）。新增任何旁挂 entry 类型时，fork/resume 的重播种路径要同步设计。
4. **大文件读路径决定产品上限**：claude-code 64KB lite 读+边界跳读+50MB 上限三层防御、codex 倒序寻址读，支撑「会话列表/老会话不全量加载」；OpenHands 页缓存专治对象存储读放大；gemini-cli 全量读是服务端多会话场景的反例。
5. **写并发谱系可按部署形态选型**：单进程桌面（claude-code 进程内队列即可）→ 单机多进程（codex flock 文件锁）→ 服务端多会话（cline OCC+SQLite 唯一索引 / OpenHands 锁内分配 id）；全量读改写（gemini-cli 旧层、cline messages 正文）只适合单写者桌面场景，正文写建议补原子 rename。
