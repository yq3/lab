# 05 审计与成本数据的持久化（codex / ai-hedge-fund / SQLBot / Vibe-Trading / supersonic / gpt-researcher / FinRobot / OpenHands）

> agent-persistence 轮第 5 路。聚焦「一行审计/成本记录长什么样、写到哪、何时写、怎么读回」。基线：codex@ee6814bfa4 / ai-hedge-fund@fc1bf250ea / SQLBot@ba9aa5db66 / Vibe-Trading@f84b2977a5 / supersonic@6919ac50be / gpt-researcher@6f998577d5 / FinRobot@6d6ccd3 / OpenHands@e8249f00a。
>
> **综述**：8 仓覆盖四种介质——JSONL 事件流（codex/OpenHands/Vibe）、按内容寻址的单 JSON 文件（ai-hedge-fund）、关系表 DDL（SQLBot/supersonic/FinRobot）、单文件 JSON 字典 + 原子替换（gpt-researcher）。共同点：审计写入几乎全部走**独立于业务返回路径的旁路**（中间件/装饰器/事件流入口），失败均不阻断主流程（fail-open 于可用性、fail-closed 只出现在 Vibe 的链验环节）。分野在**计量对象**：codex/OpenHands 记 token 明细、gpt-researcher 折算 USD、SQLBot 存原生 usage JSON、supersonic/FinRobot 只记查询耗时，ai-hedge-fund 干脆不记成本只记「决策可回放」。

## 1. codex（Rust）：rollout JSONL 里的 TokenUsageRecord 与 SecurityRiskScore

**JSONL 行结构**：每行 = `{timestamp, ordinal?, item}`，timestamp 为 UTC RFC3339 毫秒，item 是 flatten 进来的变体（`codex-rs/rollout/src/recorder.rs:2040-2074`）。`token_usage_record` 与 `security_risk_score` **无条件持久化**（`codex-rs/rollout/src/policy.rs:18-24`）。

**TokenUsageRecord**（`codex-rs/protocol/src/protocol.rs:2253-2264`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| thread_id / session_id | ID | 会话/线程归属 |
| turn_id / root_turn_id | String | 当前轮 + 根轮（子 agent 归并） |
| response_id | String | **对应单次 API 响应** |
| usage | TokenUsage | 本次响应增量 |
| turn_token_usage / thread_token_usage | TokenUsage | 轮内/线程累计快照 |

TokenUsage 六分类：`input_tokens / cached_input_tokens / cache_write_input_tokens / output_tokens / reasoning_output_tokens / total_tokens`（protocol.rs:2231-2251）。**无 model、无时间字段**——时间在行 envelope，模型在 TurnContext 项；record 本身无 timestamp。累计逻辑：同 turn 累加 turn_token_usage、无条件累加 thread_token_usage（`core/src/state/session.rs:202-238`）。

**写入时机 = 每次 API 响应完成**：`ResponseEvent::Completed` → `record_observed_response_completed` → `persist_rollout_items(&[TokenUsageRecord])`（`core/src/session/turn.rs:2806-2812`）；compaction 路径同样上报（compact.rs:810）。

**SecurityRiskScore**（`codex-rs/protocol/src/security_risk.rs:13-25`）：`scores: BTreeMap<String,f64>`（当前只有 `action_risk`，high→1.0 / low→0.0）、`call_id`（被评工具调用）、`action`（被审的 bounded tool action 原文 JSON）、`sampled_at`。写入方是 Guardian V2 异步打分器：采样分类成功且为该 tool_call 最新样本时，`persist_scores && !ephemeral` 才落盘（`codex-rs/ext/guardian-v2/src/async_scorer/extension.rs:689-757`）；失败走 fail-closed 兜底分（:761）。

**Guardian 其他持久化**：`GuardianAssessment/GuardianWarning` 事件明确列为 transient **不进 rollout**（policy.rs:144,157）；Guardian 历史靠 `GuardianHistoryCheckpoint` 嵌在 CompactedItem 里跨压缩存活（history/src/lib.rs:187,193）。**读回**：会话重建倒扫 rollout 取 latest TokenUsageRecord（`core/src/session/mod.rs:1726-1729`）；CompactedItem 内嵌 `latest_token_usage_record` 快照使 resume 不必远扫（history/src/lib.rs:202-206）。

## 2. ai-hedge-fund：PromptCache「三合一」

**目录与命名**：`~/.hedge-fund/cache/llm/<key>.json`，key = `sha256(f"{agent}|{model}|{system}|{user}").hexdigest()[:24]`（`hedge_fund/llm/cache.py:9-10,25-28`；抽查复核命中 :28）。

**单文件 JSON 结构**（`hedge_fund/signals/llm_agent.py:75-94`）：

| 字段 | 三合一角色 |
|---|---|
| agent / model | 审计：谁 + 用哪个模型决策 |
| ticker / as_of | 审计：标的与时点 |
| snapshot_hash | 审计：PIT 输入快照指纹（`FundamentalsSnapshot.content_hash`） |
| system / user | 审计：**精确 prompt 原文**（user 即渲染后的快照） |
| response | 缓存：命中即免调用 → 回测重跑 $0 |
| parsed 或 parse_error | parsed=缓存命中键；parse_error=调试踪迹（解析失败原始响应留盘） |
| created_at | put 时补 UTC ISO（cache.py:46） |

**读写时机**：`predict()` = build_snapshot → 拼 prompt → key → `cache.get(key)`；命中含 `parsed` 直接产 Signal（cached=True，零 LLM 调用）；未命中 → `llm.complete` → `put(record+parsed)`，解析失败 `put(record+parse_error)` 后 abstain（llm_agent.py:54-95）。**$0 重放原理**：新日期但基本面快照未变 → content_hash 不变 → prompt 不变 → 同 key 命中（`test_llm_agents.py:144-156`）。Signal.metadata 回传 prompt_key/snapshot_hash/cached 供上层对账（llm_agent.py:153-161）。损坏文件按 miss 处理重写（cache.py:41-42）。⚠️ 无 TTL/淘汰机制、无进程锁，单写者假设。

## 3. SQLBot：chat_log 执行面 + @system_log 管理面

**chat_log DDL**（`backend/apps/chat/models/chat_model.py:66-82`）：

| 列 | 类型 | 说明 |
|---|---|---|
| id | BigInteger Identity PK | |
| type | varchar(3) 枚举 | 仅 `CHAT='0'` |
| operate | varchar(3) 枚举 | **14 种操作**（见下） |
| pid | BigInteger | 父级日志 ID，串起一轮对话的步骤链 |
| ai_modal_id / base_modal | BigInteger / varchar(255) | 模型 ID + 基础模型标识 |
| messages | JSONB | 完整 prompt 消息数组 |
| reasoning_content | Text | 推理内容（思维链） |
| start_time / finish_time | DateTime | 无时区 |
| token_usage | JSONB | 原生 usage dict 整体入库 |
| local_operation / error | Boolean | 是否本地操作 / 是否出错 |

operate 取值 `'0'-'13'`：GENERATE_SQL, GENERATE_CHART, ANALYSIS, PREDICT_DATA, GENERATE_RECOMMENDED_QUESTIONS, GENERATE_SQL_WITH_PERMISSIONS, CHOOSE_DATASOURCE, GENERATE_DYNAMIC_SQL, CHOOSE_TABLE, FILTER_TERMS, FILTER_SQL_EXAMPLE, FILTER_CUSTOM_PROMPT, EXECUTE_SQL, GENERATE_PICTURE（chat_model.py:35-49）。**写入时机**：每次 LLM 调用前 `start_log()` 先插行，完成后 `end_log()` 回填 finish_time/messages/reasoning_content/token_usage（`backend/apps/chat/curd/chat.py:869-890+`）；EXECUTE_SQL 等无 LLM 步骤靠 local_operation=True 区分留痕。**读回**：`get_chat_log_history` 聚合出 ChatLogHistory{duration 秒, total_tokens, steps[]}（curd/chat.py:580-697）。

**@system_log 管理面**：`sys_logs` 表（`backend/common/audit/models/log_model.py:60-79`）：operation_type/operation_detail/operation_status(success|failed)/ip_address/user_agent/**execution_time(BigInteger 毫秒)**/error_message/create_time/module/oid/resource_id/request_method/request_path/remark/user_name/resource_name。附表 `sys_logs_resource(log_id, resource_id, resource_name, module)`（:51-57）。装饰器实现（`backend/common/audit/schemas/logger_decorator.py`）：
- **IP 代理链**：x-forwarded-for（取第一跳）→ x-real-ip → cf-connecting-ip → x-client-ip → forwarded（RFC7239 `for=` 解析）→ 兜底 socket（:124-165）。
- **敏感 header 排除**：authorization/cookie/set-cookie 三键跳过，body 只记 content-type/content-length（:375-389）。⚠️ request_params 传入构造但模型无此列，实际不落库。
- **DELETE 补录**：资源删除后按 resource_info_list 批量 UPDATE `sys_logs_resource.resource_name`，保住被删资源的可读名（:472-481）。

## 4. Vibe-Trading：哈希链账本

**record schema**（`agent/src/live/audit.py:172-245`）：`audit_id("la_"+uuid4hex) / ts(ISO8601 UTC 毫秒) / session_id / kind / intent_normalized / **mandate_snapshot_ref**（授权链上半：哪份 mandate）/ **consent_record_ref**（下半：哪次人工同意）/ broker_request / broker_response / outcome / gate_decision / server / remote_tool / error`——写前统一 `redact_payload()` 脱敏。kind 7 值：order_placed / order_cancelled / **order_rejected** / mandate_committed / breach / **halt_tripped** / halt_cleared（audit.py:124-132）——**被拒与 halt 是一等记录**；outcome 5 值：accepted/filled/rejected/error/blocked。

**链字段**（`agent/src/governance/ledger.py:92-149`）：payload 之上叠 `seq`（1 起）+ `prev_record_hash`（首条哨兵 `"sha256:genesis"`）+ `record_hash="sha256:"+sha256(canonical_json({seq,prev_record_hash,payload}))`，canonical=sort_keys+compact（:124-130）。payload 禁带三个保留键（:408-410）。

**介质**：`<runtime_root>/live/audit.jsonl`（经典账本，append+fsync、目录 0700）+ `<runtime_root>/live/audit_chain.jsonl`（哈希链账本，`chain=True` 时双写；audit.py:120-121,149-169,303-341）。**append 前验全链**：持锁读全文 walk，断链抛 `LedgerCorruptionError` 拒绝延伸（ledger.py:368-469）——O(n)/append 是明说的取舍（docstring:36-47）。**flock 单写者**：`_lock_exclusive` fcntl.flock / msvcrt 字节锁（:327-351），定位是防并发算重 seq 的 liveness 优化，防篡改靠验链本身。**durability**：每写 fsync + 新建文件 fsync 父目录（:453-467）。**轮转**：64MiB 封存 `audit_chain.0001.jsonl` 永不删除，跨段续链、整段删除在接缝可检（:595-738）。**离线举证**：build_export 带 export_hash 的自证 envelope，verify_export 无源文件可验（:496-585）。**链写失败不阻断下单**：经典账本已落盘，链缺口留给 verify_chain 检出（audit.py:320-341）。⚠️ docstring 称 chain 默认 False，实际签名 `chain: bool = True`（audit.py:253）——文档与代码不一致。

## 6. gpt-researcher：成本归集与两份 JSON

**add_costs**（`gpt_researcher/agent.py:773-789`）：`research_costs: float` 总额 + `step_costs: dict[str, float]` 分步；非数字抛 ValueError；有 log_handler 时发 `cost_update` 事件 {cost, total_cost, step_name}。**_current_step 归集**：生命周期置位 general→deep_research→research→report_writing（agent.py:167,352,356,379,472），`cost_callback` 贯穿 retriever/context_manager/writer——按「调用发生时当前阶段」归属。**计价**：`calculate_llm_cost` 优先 API 上报 usage（OpenAI cache_read 按 50% 折价；Anthropic 单独价目表 cache write 1.25x/read 0.1x），无 usage 才 tiktoken 估算（`utils/costs.py:197-316`，价目硬编码 :31-62）。

**report_store.py**：单 JSON 文件 `{report_id: report}`；`asyncio.Lock` 串行化全部读写；写走 `.tmp`+`replace` 原子替换；读失败容错返回 {}（`backend/server/report_store.py:7-57`）。report 字段：id / question / answer / orderedData[] / chatMessages[] / **timestamp(ms，写时取 max 防 .old 覆盖 new)**（`backend/server/app.py:206-243`）。**JSON 日志 handler**：`JSONResearchHandler` 结构 `{timestamp, events[], content{query, sources, context, report, costs}}`，log_event 追加后全量重写（`utils/logging_config.py:8-36`）。

## 7. FinRobot：request_logs

**DDL**（`finrobot_equity/web_app/database/models.py:56-76`，SQLite）：id / user_id(FK) / email(255, index) / endpoint(255, index) / method(10) / request_body(Text) / response_status(Integer) / ip_address(50) / user_agent(Text) / **duration_ms(Integer)** / created_at(index)。**写入点**：`RequestLoggerMiddleware.dispatch`（`middleware/request_logger.py:12-105`）——SKIP_ENDPOINTS 白名单跳过状态轮询/静态；POST/PUT/PATCH body 仅 <10KB 才读、截 5KB 存；响应后落库，失败 print 吞掉（fail-open）。❌ 无 LLM token/成本字段——纯 HTTP 访问审计。

## 8. OpenHands：写时脱敏与 secret 存储

**_replace_secrets**（`openhands/events/stream.py:221-244`）：递归遍历事件 dict；顶层保护字段 `{timestamp,id,source,cause,action,observation,message}` 跳过（仅顶层，嵌套仍替换）；str 值对 secrets 逐一 `str.replace(secret, '<secret_hidden>')`——**占位符为 `<secret_hidden>`**。**调用时机**：`add_event` 内、事件进存储的唯一入口——`event_to_dict → _replace_secrets → event_from_dict`（脱敏对象回填，**内存订阅者也只见脱敏版**）→ write page → `file_store.write(json)`（stream.py:163-203）。**secret 清单来源**：① LLM/git provider tokens：`ProviderHandler.set_event_stream_secrets → expose_env_vars`（`integrations/provider.py:415-428`）；② 用户自定义 secrets：`custom_secrets_handler.get_env_vars()`（`server/session/agent_session.py:155-163`）；汇入内存 dict（stream.py:215-219）。**secret 本身存储**：FileSecretsStore 在 file_store 上以 `secrets.json` 单文件存 `provider_tokens` 等（`storage/secrets/file_secrets_store.py:15-34`）。**事件级成本**：Action 附 `llm_metrics`（accumulated_cost + accumulated_token_usage 深拷贝，`controller/agent_controller.py:1195-1207`；Metrics 定义 `llm/metrics.py:57-88`：TokenUsage{prompt,completion,cache_read,cache_write,context_window}）。

## 11. 设计结论（5 条）

1. **成本记录要进一等持久化类型而非日志**：codex 把 TokenUsageRecord 做成 rollout 变体（policy 无条件持久化 + CompactedItem 内嵌快照供 resume 快速恢复），对比 gpt-researcher 只活在内存 + 全量重写 JSON——前者可对账、可分页、可重建，后者进程死即丢。
2. **token 分类六字段是当前最细公约**：input/cached_input/cache_write/output/reasoning_output/total（codex）覆盖了折价计费所需全部输入形态；只记 total 的表日后无法回溯补算金额。
3. **审计即缓存是成本最优起点**：ai-hedge-fund 用 `sha256(agent|model|system|user)[:24]` 内容寻址 + snapshot_hash 绑定输入，一个文件同时满足回放/审计/调试，零额外表结构；代价是无淘汰无并发控制，适合单机研究型负载。
4. **金额在入库处折算、价目表独立维护**：gpt-researcher 区分 cache 折价率的硬编码价目——价目变更不需重放历史 token；反之若只存金额不存 token，价目纠错无从重算。token 与金额**双记**（OpenHands 式）才闭合。
5. **审计写入统一旁路 + fail-open，防篡改单点 fail-closed**：SQLBot 装饰器/FinRobot 中间件/supersonic 异步 insertOrUpdate 全部「审计失败不影响业务」；唯 Vibe 在 append 前验链环节 LedgerCorruptionError 硬拒——可用性与完整性的分界线画在「追加新记录」vs「在被污染历史上追加」之间，值得照抄。
