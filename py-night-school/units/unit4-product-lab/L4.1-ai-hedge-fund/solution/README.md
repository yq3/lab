# 参考答案

先完成练习再进来。对照要点：不追求与你的写法一致，追求**通过验收 + 读得舒服**。

- ex1 的核心是那个 `continue`：弃权票在进任何累加器之前就被请出循环体——分子分母
  天然同剔；`conviction = ... if weight_total > 0 else None` 一行同时守住全弃权与
  权重全零两个边界（下游拿 None 才会 ESCALATE，拿到 0.0 就成了假中性）。
- ex2 与产品 llm/cache.py 逐行同构：key 是四字段拼接串的 sha256 截 24 位（拼接天然
  确定，§5 坑位的正面教材）；get 对损坏文件 except 后返回 None；put 建目录、补
  created_at、写文件三步——「审计字段不靠调用方自觉」是这条设计的灵魂。
- ex3 的两段顺序就是幂等的来源：先单笔封顶，缩只会变小，缩完不可能重新违反单笔
  上限；等比缩用 int() 向下取整，总和只会更低于上限；批次级事件记缩后真总和
  （sum(clamped.values())）而不是上限值——验收拿它与结果表对账，记上限值就对不上。
