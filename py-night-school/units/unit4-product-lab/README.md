# Unit 4 开源产品实战

> 从「读过架构」到「跑过、改过」。三个产品同一条递进线：**无框架纯 Python → LangGraph 实战 → 治理合规架构**，全部金融/财务域。
> 递进线还有第二条读法——风控嵌入位置的光谱（观点→决策→处置→授权→执行）：L4.1 爬到处置层，L4.2 停在决策层，L4.3 直达授权层+执行层。产品实力越接近真实资金，代码级风控越完整。

## 学法说明（先读这段）

- **每课两个层次，主线离线可验收**：课程主线是把产品的**核心机制抽取成对版机制件**（锚定产品 commit，结构对版、域换成报销——`data/expense/review_mock.json` 继续当唯一素材来源），`uv run pytest` 零 key 三态全绿；**在自己克隆上真跑产品是可选加餐**（需要各家 API key / Docker），跑不了不影响毕业——先例 L3.7 的「平台课」同款约定：主线测得动的东西进 pytest，测不动的东西写成导读。
- **为什么「抽取」而不是「内置」**：三个产品都是上万行的活仓（ai-hedge-fund 75 个 py、TradingAgents 145 个、Vibe-Trading 1700+ 个），塞进课时目录既不可能也不该——我们抽的是**机制**（层级投票 / 条件边辩论 / fail-closed 检查链），锚的是**源码路标**（`仓库@commit#路径`），读生产代码不读玩具。
- **明线第三次换装**：Unit 2 手写报销审查、Unit 3 四框架同题重做，本单元把三个产品的机制映射到报销域的三种场景——**初审 = 层级投票**（各检查维度独立投票、算术合成、clamp 异常）、**争议 = 辩论-裁决**（申请方与合规方固定轮次对抗、deep 模型裁决）、**付款 = 治理链**（proposal 无权 + 代码门裁决 + mandate 授权 + 哈希链问责）。这组映射不是我们发明的，是调研报告 dimensions/A §2 的官方结论。
- **宣称 vs 实现落差警告**（A 组通病）：TradingAgents README 写着「PM 审批后送模拟交易所执行」——代码里没有 approve/reject 分支、没有任何 broker 调用；ai-hedge-fund 的 paper/live/ledger 全是 roadmap；FinRobot 的辩论架构在闭源 V2。**评估开源产品，能力清单必须逐条对码**——本单元每课都会演示一次「对码」。
- **零 key 底线不变**：L2.3 的本地 mock 端点（协议级测试替身，Java 同学理解为 WireMock）继续服役；L4.3 干脆零模型调用——治理链本来就不该信任 LLM。

## 节奏建议（三周，W11–13）

- 第 1 周：L4.1（无框架哲学：把拓扑压扁成纯函数管线，可审计性天花板）；
- 第 2 周：L4.2（LangGraph 实战：Unit 3 的图语义第一次在真实产品里全员登场）；
- 第 3 周：L4.3 + 里程碑（治理链精读 + 三个改造收口）。

时间紧的调节旋钮见 CURRICULUM §5（「想尽快到毕业设计」只做 L4.1）。每课完成判据与全学段一致：`uv run pytest` / `uv run ruff check .` / `uv run pyright` 三条同时全绿（本单元练习是**改造题**：在能跑的机制件上完成指定修改）。

## 里程碑（本学段结业判据）

独立完成 [milestone/](./milestone/README.md)：**三个产品各 1–2 个可复现改造 + 三份改造说明**。改造在你自己的产品克隆本地分支上完成（加餐），改造说明按模板写成「改什么 / 为什么 / 最小 diff / 复现步骤 / 证据（日志摘录）」；里程碑目录自带复现工作台，子进程重跑三课机制件的共用验收脚本（三课全绿才算数——跨课重验不进 pytest，是学员动作，先例 Unit 3 milestone）。

## 与前后学段的接口

- 对上游：Unit 3 的决策表是选型地图，本单元是「地图上走一遍」——mini-agent 对照组在每课讲义里继续出现（层级投票对照你手写的注册表分发、辩论循环对照你手写的 while 重试）；
- 对下游：**毕业设计的三块蓝本全部在本单元**——L4.1 的加权合成与 clamp（L5.1 确定性执行器）、L4.2 的条件边循环与 REVIEW 哨兵（L5.1 重规划回环 / L5.4 输入卫生）、L4.3 的检查链与哈希链（L5.4 执行门 / L5.3 审计账本）。毕业设计不是从零写，是把这三块装进你自己的图。

## 离毕业又近的一块

本学段结束你将拥有：三个真实产品的机制级实跑经验（读开源 agent 代码的肌肉）、风控五层光谱的完整体感（哪层是文案、哪层是代码、哪层是物理不可达）、毕业设计全部三块蓝本的亲手复刻。剩下的只有一件事：把它们组装成一个产品——那就是 Unit 5。
