# 参考答案

先完成练习再进来。对照要点：不追求与你的写法一致，追求**通过验收 + 读得舒服**。

- ex1 的骨架是「校验门的三层」：JSON 解析（已给）→ TypeAdapter 带判别联合校验 +
  首错映射（你的 TODO）→ 白名单显式再查（你的 TODO）。首错策略是刻意的：回喂给 planner
  的原因要短而准，一次修一处。白名单那层在 Literal tag 之后「不可达」，但它把规则显式化
  ——讲义 §5 的坑位会告诉你「不可达」和「不设防」是两回事。
- ex2 的关键是那行字典推导：`step.model_dump()` 减去三个元数据字段，剩下的就是工具入参
  ——executor 因此对「新增步型」零改动（纯 dispatcher 的含义）。两个 raise 的顺序先白名单
  后占用检查：白名单是安全边界（对照 L4.3 fail-closed），占用是数据完整性边界。
- ex3 的两个分支体各只有一行核心：拒绝分支返回 `[outcome]`（列表！reducer 收列表）、
  路由的边界条件是 `<= MAX_REPLANS`（代入第 3 次拒绝验证：3 <= 2 不成立 → escalate，
  replans = 3 - 1 = 2 恰好用满）。写错成 `<` 的话，第 2 次拒绝就提前 escalate——
  test_always_dirty 的 planner 轮数断言（恰好 3 轮）会当场红。
