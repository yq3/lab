# 参考答案

先完成练习再进来。对照要点：不追求与你的写法一致，追求**通过验收 + 读得舒服**。

- ex1 的关键是处理顺序：围栏 → 大括号 → 报错，一层兜一层；「找不到」与「语法错」
  是两种失败，报错信息分开——修复指令回喂时模型才知道该改什么。
- ex2 与讲义 `ask_structured` 同构，最重要的纪律是「先入史再校验」——成功路径的
  assistant 消息也要进历史，否则审计轨迹缺最后一环。
- ex3 的 normalize 只做「收窄方向的容错」（大小写/空格），值域判定永远 fail-closed：
  未知 REJECT 原因抛错而不是猜一个最像的——财务域里「猜结论」是最贵的那类事故。
