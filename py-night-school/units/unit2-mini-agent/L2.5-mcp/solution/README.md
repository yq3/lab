# 参考答案

先完成练习再进来。对照要点：不追求与你的写法一致，追求**通过验收 + 读得舒服**。

- ex1 的工具体就是 L2.2 get_claim 的搬运——装饰器一行没变，说明「工具的跨进程化」
  对工具作者几乎零成本；变化的只有运行时位置（本进程 → server 进程）。
- ex2 是「协议接轨点」的全部代码：三行透传。两套协议都选了 JSON Schema 描述参数，
  桥接才有这么薄的一层——如果一边是 Java 反射签名，这层就得厚十倍。
- ex3 的 is_error 分流是 MCP 与 OpenAI 协议的一个语义差：MCP 有显式的错误位
  （业务失败照样回 content），OpenAI 侧没有——所以桥接时要把 is_error 翻译成异常
  或 error JSON，别把失败静默当成功。
